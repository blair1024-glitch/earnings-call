# 🎙️ 台股法說會重點

選一檔股票（下拉挑或直接輸入代號／名稱），看它**每一次法人說明會**的
**未來方向摘要**、官方簡報與相關報導，場次預設停在**最新一場**。

純靜態網站，沒有相依套件、沒有 build 步驟、**執行時沒有任何外部請求**。
資料由 GitHub Action 每天抓好、寫成靜態檔案 commit 進 repo。

## 🗂️ 資料從哪裡來

| 來源 | 拿到什麼 | 說明 |
| --- | --- | --- |
| **公開資訊觀測站（MOPS）** | 法說會**場次**：日期、時間、地點、擇要訊息、官方簡報 PDF、影音 | 官方資料，法說會本身最權威的來源 |
| **TWSE / TPEx OpenAPI** | 上市＋上櫃**全部公司**的代號與簡稱 | 讓輸入框可以即時顯示股票名稱 |
| **Google News RSS／經濟日報 RSS** | 法說會相關報導的**標題、日期、原文連結** | 以經濟日報為主；**只存連結，不抓取也不轉載內文** |
| **TWSE / TPEx 綜合損益表 OpenAPI** | 營收、營業毛利、營業利益、稅後淨利 | 用來算三率，見下方「財報體質」 |
| **Claude API** | 把上面兩者整理成「未來方向」條列 | 只在 Action 裡跑，見下方「未來方向」 |

### 報導是怎麼挑的

只靠日期視窗會撈進一堆無關新聞（實測中華電一檔掛了 158 則，第一則還是月營收快報），
所以掛載規則是三道：

1. **日期視窗**：法說會前 5 天到後 25 天（會前有預告、會後有解讀）
2. **標題相關性**：要真的提到法說／法人說明／業績發表／財報／營運展望／季報
3. **數量上限**：每場最多 6 則、每檔近期報導最多 12 則，依相關性與日期接近程度排序

無關又不在任何場次視窗內的直接丟棄。以 12 檔精選股實測是 2193 則 → 327 則掛到場次
（精選清單後來擴到 54 檔，數量會等比放大）。

> 交易所簡稱帶的註記會先拿掉再去查 —— 「國巨\*」的星號、「世芯-KY」的 -KY
> 都不會出現在新聞標題裡，照原樣拿去查只會查不到東西。

### 一場法說會會看到什麼

1. **🔭 未來方向** —— AI 依報導標題整理的前瞻條列（見下一節）
2. **📌 重點整理** —— 你自己寫的（見下方 `notes.json`）
3. **📰 相關報導** —— 標題＋日期＋連結，經濟日報排最前面
4. **官方簡報 PDF ／影音** —— 最權威，點進去看原始資料

## 🔭 未來方向（AI 摘要）

法說會的價值在**前瞻指引** —— 財報講的是已經發生的事，法說會講的是下一季要幹嘛。
所以每一場都會有一塊「未來方向」，用條列講這家公司接下來的展望、目標與時程。

### 為什麼原料只有新聞標題

實測過三種材料，只有一種真的帶前瞻資訊：

| 材料 | 覆蓋 | 結論 |
| --- | --- | --- |
| MOPS 擇要訊息 | 場次全有，中位數 **35 字** | 幾乎都是「公司營運簡介、ESG、公司未來展望」這種議程標題，沒有實質內容 |
| 新聞標題 | 覆蓋少，但密度高 | 「聯發科法說2》估Q3營收年增7％至12％上看1598億元 第2代AI ASIC預計2028年初量產」——**標題本身就是指引** |
| 官方簡報 | 抓得到（見下方） | 目前只在畫面上放連結，**還沒**拿來當摘要原料 |

所以摘要的輸入就是「該場的新聞標題 ＋ MOPS 擇要訊息」，沒有別的。
**一樣不抓、不轉載任何新聞內文。**

### 防幻覺：不是只靠 prompt

在 prompt 裡寫「不要編數字」是請求，不是保證。所以模型回來之後還要過
`scripts/summarize.py` 的 `verify_outlook()`，**逐條驗證、過不了就丟掉**：

- 條目標的 `src` 對不到任何一則報導 → 丟掉
- 條目裡出現的數字，只要有一個在輸入原文裡找不到 → 丟掉
  （比對前會把全形數字與千分位正規化，所以「１,５９８」和「1598」對得上；
  但把 1598 寫成 1600 會被擋下來）
- 全部條目都被丟光 → **這場不產生摘要**，前端整張卡不顯示

這個驗證器是純函式、不連網，`scripts/test_parsers.py` 有離線測試守著。

畫面上每一條都附**出處連結**，指回它引用的那一則報導，可以直接點過去對。

### 📄 官方簡報連結是怎麼拿到的

一開始 `deck` 是 **0 / 9740 場**全空，因為 MOPS 那一格的 `href` 就是 `"#"`。
`--probe-deck` 把真實 HTML 印出來之後才發現，檔名其實寫在 `onclick` 裡：

```html
<a href="#" onclick='document.fm_fileDownload.fileName.value="121620260810M001.pdf";
                     document.fm_fileDownload.submit();'>121620260810M001.pdf</a>
```

而頁面上的 `fm_fileDownload` 表單指向 `/server-java/FileDownLoad`，
其餘參數（`step=9`、`filePath=/home/html/nas/STR/`、`functionName=t100sb02_1`）全是固定值。
所以只要把檔名挖出來就能組出直連。檔名本身是 `代號＋日期＋序號`，附檔名有 `.pdf` 也有 `.pptx`。

**不靠表頭關鍵字去找那一欄** —— 第一版是這樣寫的，結果 `deck` 整批還是空的，
因為那一欄的表頭對不到「中文」或「簡報」任何一個。現在改成整列掃過去，
哪一格的 `onclick` 有 `fm_fileDownload.fileName` 那格就是簡報。這個特徵夠獨特，不會誤判。

資料檔裡 `deck` 存的是**檔名**而不是完整網址，9000 多場省下大量重複的固定參數；
完整連結由前端用 `meta.deck` 組出來。

> 網址是我們自己組的、不是頁面上現成的連結，所以每次抓取都會**實際下載一份驗證**：
> 先試 GET（前端就是一個單純的 `<a>`），不行再試 POST（前端畫成送出表單的按鈕，
> 一樣只有按下去才會發請求，頁面載入時仍然零外部請求）。
> 兩種都驗不過就整批不輸出 —— 網站上寧可沒有這個按鈕，也不要放一堆點下去是錯誤頁的「官方簡報」。

### 費用

輸入有指紋（fingerprint）—— 標題沒增減、內容沒改動就不會重打 API。
所以**日常執行幾乎不花錢**，只有新場次或新掛上的報導會觸發。
用 `claude-opus-5`，每場約 600 in / 300 out token，換算下來一場不到 NT$0.5。
另外 `config.json` 的 `maxSummaryCalls` 是硬上限，程式出錯也燒不掉錢。

### 要設定的東西（只有一件）

**Settings → Secrets and variables → Actions → New repository secret**，
名稱填 `ANTHROPIC_API_KEY`，**值填金鑰本身**（`sk-ant-` 開頭的那一長串）。

> ⚠️ 2026-08-12 連兩次執行都是 `401 invalid x-api-key` —— secret 的**值**被填成了
> 「ANTHROPIC_API_KEY」這串字。名稱和值是兩個欄位，別填反了。
>
> 怎麼分辨是名稱錯還是值錯：**名稱錯** → log 會說「沒有設定 … → 跳過摘要」，
> 一次 API 都不會打；**值錯** → 會真的打出去然後拿到 401。看到 401 就是值的問題。
>
> 想確認有沒有設對，跑一次 `probe` 模式就好 —— `summarize.py --probe` 會印出
> 金鑰長度、是不是 `sk-ant-` 開頭，並**實際打一次 1 token 的請求**（成本趨近於零）
> 確認它真的有效。不印任何金鑰內容。

沒設定的話這個功能會**靜默跳過**：log 會印一行警告，`summaries.json` 原封不動，
其餘資料照常更新，build 不會失敗，網站其他部分完全不受影響。

### 呼叫失敗不會污染快取

指紋機制有個陷阱：如果把「API 呼叫失敗」也記進快取，指紋一寫下去，
**那一場之後就永遠不會重試了**。第一次執行就是這樣 —— 200 場 401，
卻全被記成「材料不足」。

所以 `_ask()` 回的是三態，只有 `empty`（呼叫成功但材料撐不出東西）會寫快取，
`error` 一律不寫，下次執行自動重試。另外遇到設定層級的錯誤（401 之類）會
**整批中止**，不會把配額白白打完。`test_parsers.py` 有測試守著這件事。

## 📊 財報體質（三率三升）

選完股票會多出一塊「財報體質」，算的是法人常講的**三率**：

| 率 | 算法 | 反映什麼 |
| --- | --- | --- |
| 毛利率 | 營業毛利 ÷ 營業收入 | 產品組合、定價能力、成本結構 |
| 營業利益率 | 營業利益 ÷ 營業收入 | 費用控制與營運槓桿 |
| 稅後淨利率 | 母公司業主淨利 ÷ 營業收入 | 業外損益與稅負有沒有拖後腿 |

三個都比基期高就是**三率三升**。比較基期優先用**去年同季（YoY）**——這是法人的
標準比法，可以避開淡旺季干擾；歷史不足時退回**上一季（QoQ）**，畫面上會明確標示是哪一種。

### 為什麼要獨立成一塊

財報是**落後指標**，法說會談的是**下一季展望**，兩者時間軸不同，混在一起看會誤導。
所以三率放在法說會區塊之外，各自標清楚。

### 刻意的設計取捨

- **金融、保險、證券業不適用**：這些產業的損益表沒有「營業毛利」這一欄，
  硬套公式只會算出垃圾。偵測到缺這欄就標「不適用」，不會生一個數字出來。
- **三個數字一律攤開顯示**，不只給一個綠燈。處分資產、匯兌等一次性業外收益
  會讓稅後淨利率虛升，出現「三率三升但獲利品質不佳」，只看結論會被騙。
- **不輸出任何買賣訊號**。這是描述過去財報的計算結果，不是預測。

### 歷史是怎麼累積的

TWSE / TPEx 的損益表 OpenAPI 通常**只吐最新一季**，但回應帶了「年度」與「季別」。
所以每次 Action 執行都會把該季數字存進 `data/financial_history.json` 累積起來，
之後就能拿同一季跟去年同季比。

> 這代表**剛上線時大多數公司會顯示「還沒有可比較的基期」**，
> 要等歷史累積夠了才會出現 YoY 判斷。這是正常的，不是壞掉。
> 想立刻有完整歷史，就得改成從 MOPS 逐檔抓歷史財報（請求量大很多）。

### ⚠️ 涵蓋率的已知限制

2026-08-11 實測：三率只涵蓋 **604 家**，台積電(2330)、鴻海(2317)、廣達(2382)
等大型股**不在其中**，所以這些股票暫時不會出現「財報體質」區塊。

已經排除的可能原因：

- **不是程式漏抓** —— 診斷顯示這些公司根本不在 API 回應裡
- **不是端點選錯** —— 營益分析彙總表與六類綜合損益表交叉比對，回的是**同一批 604 家**

**合理推論（尚未證實）**：所有資料集的 `出表日期` 都是查詢當天，而台積電 Q2 是
7/16 就公布的，所以這些資料集可能反映的是**近期申報批次**而非整季累積。
Q2 申報期限是 8/14，這幾天資料應該會變多；由於本專案每天把當季數字累積進
`data/financial_history.json`，涵蓋率應該會自己補齊 —— 但需要連續幾天觀察才能確認。

如果幾天後仍卡在 600 多家，就得改從 MOPS 逐檔抓財報（請求量大很多）。

`data/financial_history.json` 由程式維護，請勿手動編輯。

## ✍️ 手動補充法說會重點

編輯 `data/notes.json`：

```json
{
  "2330": {
    "2026-07-16": [
      "毛利率優於財測上緣，主要來自產品組合改善",
      "全年美元營收成長目標上修",
      "先進封裝產能明年續增"
    ]
  }
}
```

- 外層 key 是**股票代號**，內層 key 是**法說會日期**（`YYYY-MM-DD`）
- 日期要跟該場次的 `date` 對得上才會顯示。日期可以從網站上那一場直接看到
- `build.py` 每次執行都會重新併入，所以**自動抓取不會洗掉你寫的東西**

改完 commit + push 即可，下次 Action 執行就會出現在網站上。

## ⚙️ 調整設定

編輯 `data/config.json`：

| 欄位 | 意思 |
| --- | --- |
| `featured` | 下拉選單的精選清單，也是**會抓相關報導、會產生未來方向摘要**的名單。目前 54 檔。抓新聞逐檔發請求（每檔約 4 秒），別放太多 |
| `months` | 往回抓幾個月的法說會場次。數字越大，`earnings.js` 越大、抓取越久 |
| `fetchNews` | 設成 `false` 就只抓官方場次，完全不碰新聞來源 |
| `fetchFinancials` | 設成 `false` 就不抓損益表，網站不顯示「財報體質」區塊 |
| `fetchSummaries` | 設成 `false` 就不呼叫 Claude。沒設 `ANTHROPIC_API_KEY` 時也會自動跳過 |
| `maxSummaryCalls` | 單次執行最多呼叫幾次 API 的硬上限。超過就優先做最新的場次，其餘下次再做 |
| `searchUrl` | 查無資料時的外連樣板，`{q}` 會被代換成「公司名稱 法說會」 |

> 精選清單以外的股票**還是查得到**——`stocks.js` 有全部上市櫃公司，
> `earnings.js` 也有全部公司的場次，只是不會預先抓相關報導。

## 🤖 自動更新

`.github/workflows/update-data.yml`

- **排程**：台灣時間每天 09:00（UTC 01:00）
- **手動**：Actions → 更新法說會資料 → Run workflow
  - 勾 `probe` 可以只**探測來源端點**、印出實際回應，不動資料檔。
    MOPS 或 OpenAPI 哪天改版了，用這個模式看 log 最快
- 資料沒變化就不會產生 commit

### 來源失效時會怎樣

腳本刻意設計成**寧可不更新，也不要用空資料覆蓋好資料**：

- 股票清單抓失敗 → 不寫 `stocks.js`，網站繼續用上一版
- MOPS 抓失敗 → 不寫 `earnings.js`，直接結束（exit 1，Action 會標紅提醒你）
- 新聞抓失敗 → 場次照常更新，只是沒有相關報導
- 損益表抓失敗 → 不寫 `financials.js`，三率沿用上一版
- 沒有 API key／摘要呼叫失敗 → 該場略過，`summaries.json` 只增不減，
  已經產出的摘要不會因為來源某次抓漏而消失

## 🧪 本機開發

```bash
# 看網站（用 http server 開，才能正確測到網址參數行為）
python3 -m http.server 8899
# → http://127.0.0.1:8899/

# 解析器離線測試（不連網）
python3 scripts/test_parsers.py

# 介面行為測試（需要 node + playwright，且上面的 http server 要開著）
node scripts/smoke_ui.js

# 實際跑一次抓取（會覆蓋 data/*.js）
pip install -r scripts/requirements.txt
python3 scripts/build.py

# 只探測端點、不寫檔
python3 scripts/fetch_mops.py --probe
```

## 🎨 介面功能

- **選股票**：精選下拉，或直接輸入**代號或名稱**（`2330`、`台積電`、打「台積」也行）
- **同步顯示名稱**：邊打邊出現公司名稱與市場別；查無代號會明確提示，並仍給搜尋連結
- **場次下拉**：由新到舊，**預設停在最新一場**
- **未來方向**：AI 依報導標題整理的前瞻條列，每條標分類、附出處連結
- **財報體質**：三率數字與升降、比較基期，獨立於法說會區塊
- **記住選擇**：上次看的股票記在 `localStorage`
- **可分享網址**：`?stock=2330&call=2026-07-16` 直接開到指定場次
- **深／淺色主題**：跟隨系統，右上角可手動切換
- **響應式**：手機、平板、桌機都可讀
- **零外部請求**：沒有 CDN、沒有追蹤碼、沒有字型外連
